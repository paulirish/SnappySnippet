# SnappySnippet Under the Covers

This document provides a technical review of the SnappySnippet Chrome extension, detailing its architecture and implementation. It is intended for developers who want to understand how the extension works, and for those who are attempting to create a new implementation of it.

## Architecture

SnappySnippet is a Chrome DevTools extension that allows developers to extract the HTML and CSS of a selected DOM element and its descendants. The extension is architected as follows:

- **`devtools.js`:** The entry point of the extension. It creates a new panel in the Chrome DevTools called "SnappySnippet".
- **`panel.html`:** The HTML file that defines the UI of the SnappySnippet panel.
- **`panel.js`:** The core of the extension. It handles the UI logic, user interactions, and orchestrates the process of generating and processing the code snippets.
- **`background.js`:** A background script that is mainly responsible for managing the extension's settings.
- **`tools/`:** A directory containing various utility modules that are used to generate, process, and format the code snippets.
- **`filters/`:** A directory containing modules that apply various filters to the generated CSS, such as removing default values or vendor prefixes.

## Data Flow

The process of generating a code snippet can be broken down into the following steps:

1.  **Snapshotting:** When the user clicks the "Create Snippet" button, the `makeSnapshot()` function in `panel.js` is called. This function executes the `Snapshooter.js` script in the context of the inspected page. The `Snapshooter` traverses the DOM tree of the selected element, extracts its HTML and computed CSS, and returns it as a JSON object.

2.  **Processing:** The `processSnapshot()` function in `panel.js` takes the JSON object from the `Snapshooter` and applies a series of processing steps to it. This includes:
    -   **Filtering:** Applying various filters to the CSS, such as removing default values, shorthand properties, and Webkit prefixes.
    -   **Combining:** Combining CSS rules that have the same properties and values.
    -   **Formatting:** Formatting the HTML and CSS to make it more readable.

3.  **Output:** The processed HTML and CSS are then displayed in the text areas in the SnappySnippet panel.

## Key Components

### `Snapshooter.js`

The `Snapshooter` is the heart of the extension. It is responsible for extracting the HTML and CSS of the selected DOM element. It works as follows:

-   It is executed in the context of the inspected page.
-   It takes the selected DOM element as input.
-   It traverses the DOM tree of the element and its descendants.
-   It uses `window.getComputedStyle()` to get the computed CSS of each element, including its `:before` and `:after` pseudo-elements.
-   It clones the DOM subtree to avoid modifying the live page.
-   It assigns a unique ID to each element in the cloned subtree. These IDs are used to link the HTML elements to their corresponding CSS rules.
-   It converts all relative URLs to absolute URLs.
-   It returns a JSON object containing the HTML and CSS of the selected element.

### `CSSStringifier.js`

The `CSSStringifier` is a utility that converts the array of CSS objects generated by the `Snapshooter` into a CSS string.

### `SameRulesCombiner.js`

The `SameRulesCombiner` is a utility that optimizes the generated CSS by combining rules that have the exact same properties and values.

### Filters

The `filters/` directory contains a set of modules that are used to filter the generated CSS. These filters include:

-   **`DefaultValueFilter.js`:** Removes CSS properties that have their default browser values.
-   **`ShorthandPropertyFilter.js`:** Removes longhand properties when a corresponding shorthand property is available.
-   **`WebkitPropertiesFilter.js`:** Removes all CSS properties that start with the `-webkit-` prefix.

## Conclusion

SnappySnippet is a well-designed and powerful Chrome extension that provides a great way to extract HTML and CSS from a web page. Its modular architecture and clear separation of concerns make it easy to understand and maintain. The use of filters and processors allows for a high degree of customization and optimization of the generated code snippets.
